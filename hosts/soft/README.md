# Software framebuffer host

`hosts/soft/` is the PocketJS host with no window: the guest runs on
**QuickJS** (the device lineage, `pocket-stack/quickjs-rs`), the retained
tree, layout and animation run in `pocketjs-core`, and every frame is
rasterized by the core software rasterizer (`engine/core/src/raster.rs`,
through `engine/symbian` built `software-only`) into a framebuffer **in
memory**. Nothing is presented. The output of a run is one FNV-1a hash per
frame over the RGBA bytes, plus optional raw frame dumps — the same bytes
and the same hash the wasm oracle computes (`hosts/sim/sim.ts`,
`tools/tape.ts`), so the two hosts are comparable frame by frame.

Rendering is not skipped: the rasterizer computes every pixel of every
frame. What is skipped is presentation (blit, swap, vsync), which is
host-specific and wall-clock bound. That is what makes this host usable
without a display, deterministic, and byte-comparable across machines.

## What lives here

| file | role |
|---|---|
| `pocket_runtime.c` / `.h` | The shared QuickJS bridge: runtime creation, the complete `ui.*` op table over the C ABI, `frame()` + job drain + core ticks, hit tests, software render. Linked unchanged by the iPhone 2G / 4S, BlackBerry Classic (QNX + Android) and Meizu M8 hosts. |
| `pocket_core.h` | C declarations of `engine/symbian`'s `ui_*` ABI. |
| `pocket_spec.h` | Generated by `contracts/spec/gen-c.ts` (button mask, analog center); `tests/contract.ts` byte-compares it. |
| `pocket_input.c` / `.h` | Hardware-neutral input state machine for hosts with keys, a relative pointer and one touch contact; unit-tested with the host compiler (`tests/pocket-input.test.ts`). |
| `rust_eh_personality.c` | The no-op unwinding personality some system toolchains demand when linking the `panic=abort` core. |
| `main.c` | This host's own entry point: tape in, hashes and frame dumps out. |

`pocket_runtime.c` needs `POCKETJS_TARGET_ID` and `POCKETJS_HOST_ABI` at
compile time. Device hosts take them from the verified build plan; this
host identifies as `soft` and, because plan-less bundles embed no contract,
uses ABI `0`.

## Commands

```sh
bun tools/soft.ts doctor                       # cc, cargo, pinned nightly, QuickJS checkout, binary
bun tools/soft.ts build                        # QuickJS + engine/symbian (software-only) + main.c
bun tools/soft.ts run hero-main --frames 90 \
  --input "5:0x40,6:0,20:0x2000,21:0" \
  --capture 2,80 --png-dir dist/soft           # hashes on stdout, PNGs of frames 2 and 80
bun tools/soft.ts check hero-main --frames 90 \
  --input "5:0x40,6:0,20:0x2000,21:0"          # soft host vs wasm oracle, first divergent frame
```

`build` fetches the pinned QuickJS into `~/.cache/pocket-stack/soft/`,
builds `engine/symbian` for the host with the nightly its
`rust-toolchain.toml` pins, compiles the five QuickJS sources and the two
host files with the system `cc`, and links `.pocket-build/soft/pocket-soft`.

`--input` is the latched tape format shared with `tools/tape.ts record` and
the PSP capture build: `frame:mask` pairs, each mask held from its frame
until the next pair. Masks are the portable `POCKET_BTN_*` bits from
`pocket_spec.h`.

## The binary

```
pocket-soft --js app.js --pak app.pak [--frames N] [--input "f:mask,..."]
            [--capture f,f,...] [--dump DIR] [--hashes out.json]
            [--width 480] [--height 272]
```

One frame is one `pocket_runtime_tick`: the guest turn (`frame(buttons)`),
the job drain, one core tick at 60 Hz, then `ui_render_incremental`. The
report is JSON: `{"host":"soft","target":"soft","width":480,"height":272,
"frames":N,"hz":60,"hashes":["…"]}`.

Exit codes: `1` usage, `2` boot failed (`pocket_runtime_error()` on
stderr), `3` a frame failed, `4` I/O.

## Why a host and not a test helper

The device C hosts are this runtime plus a presentation layer. Keeping the
runtime here, with a main that needs no device, gives them a twin that runs
on any machine: bundles can be executed on the shipped engine lineage in
CI, goldens can be checked on QuickJS rather than only on Bun, and a
benchmark shell can link the exact runtime the devices run.

## Bench hooks

`pocket_runtime.c` compiled with `-DPOCKET_RUNTIME_BENCH_HOOKS` calls
`pocket_bench_stage(int stage)` — provided by the embedding program — at the
edges of its phases: `POCKET_BENCH_STAGE_EVAL` before the bundle is
evaluated, `_JS` before the guest turn (`frame()`), `_JOBS` before the job
drain, `_TICK` before the core ticks, and `_IDLE` when the runtime hands
control back. A benchmark shell reads its clock or emits a marker at each
call and attributes the interval to the stage. Without the define the macro
expands to nothing, so device hosts are unchanged. Draw and render are not
in this list: a shell that wants them separately calls the core directly
(`engine/symbian`'s `with_ui`) instead of `pocket_runtime_render`.
